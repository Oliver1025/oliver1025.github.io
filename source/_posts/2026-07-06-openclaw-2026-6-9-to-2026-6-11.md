# OpenClaw 更新解读 (2026.6.9 → 2026.6.11)

本次版本跨度约 2 天，合并 PR 共 **308 个**。OpenClaw Core 升级到 2026.6.11，微信插件（openclaw-weixin）维持 2.4.4 不变。本次重点在 **多通道控制能力增强**、**Operator 工作流工具**、**插件分发安全** 与 **Agent 长期稳定性**。

---

## OpenClaw Core 更新要点

### 多通道控制能力

各 IM 通道的可控性进一步增强，便于自动化和按场景调优：

- **Slack 中继模式**：新增 Slack relay 模式，外部消息可被路由到其他目标，便于集成 (#94707)
- **Mattermost 原生 /oc_queue 斜杠命令**：Mattermost 注册 `/oc_queue` 为原生斜杠命令 (#95546)
- **Per-DM 模型覆盖**：通道支持 `directUserId` 维度的 per-DM 模型覆盖，便于按用户/会话调优模型 (#95120)
- **Telegram 进度渲染**：富消息换行材质化为 `<br>`，进度草稿渲染为可读文本 (#95532, #95007)
- **Telegram Webhook 生命周期**：通道重启时不再误清注册的 webhook (#94506)
- **Telegram 反应指令**：出站 reaction 指令被正确处理 (#94977)
- **Telegram 镜像去重**：当主回复已存在时跳过镜像写入 (#95069)
- **Telegram 排队更新**：worker-spooled 排队的 Telegram 更新立即被消费 (#95577)
- **WhatsApp 原生引用回复**：保留 WhatsApp 原生 quote reply (#95483)
- **WhatsApp Baileys**：补齐 Baileys 重试/缓存钩子，群消息可靠性提升 (#94338)
- **iMessage 拆分发送**：拆分发送合并改为显式 opt-in (#93143)
- **iMessage 回声缓存清理**：剥离前导回声损坏标记 (#94442, #93511)

### Operator 工作流工具

- **`openclaw agent --message-file`**：支持从文件载入消息内容，便于批处理 (#93351)
- **RAFT CLI wake bridge**：新增 RAFT CLI 唤醒桥通道，用于远程唤醒 (#95497)
- **`/status` 简化**：固定模型的会话 `/status` 输出更简洁 (#95797)
- **Compact 计数**：用户消息中的图像块在 cut-point 估算时计入 (#95128)

### 插件分发与图标

- **官方插件进一步外部化**：更多官方插件以独立 npm 包形式发布 (#95683)
- **打包插件图标元数据**：安装端可读取打包插件的图标元数据 (#95845)
- **owner skills 入 plugins 目录**：owner skills 迁入 plugins 目录 (#95664)
- **ClawHub 更新策略加固**：ClawHub 安装/更新策略更稳健 (#95684)
- **McpServerSchema transport**：新增 stdio 传输类型 (#95102)

### Android 移动端

- **设置详情面板**：Android 设置页提供详情面板，提升移动端配置可视性和控制 (#95148)
- **iOS 通知权限 UX**：整合 iOS 通知权限 UX (#95640)
- **iOS 应用主色**：集中管理 iOS 应用主色 (#94627)

### Agent 长期稳定性

- **选中的 harness 插件激活**：Agent 选中的 harness 插件被实际激活 (#95652)
