OpenClaw 更新解读 (2026.6.11 → 2026.7.1)

本次是一次重大版本，跨度约 20 天，合并 PR 共 1536 个。OpenClaw Core 升级到 2026.7.1，微信插件同步升至 2.4.6（详见另一篇微信插件更新文章）。本次重点：新模型与 Provider 上线、Control UI / macOS 原生会话重构、会话式 Onboarding（Crestodian）、iOS/Android 离线与语音、会话组织与生成标题、Telegram/Codex 续聊能力、启动与升级恢复。

OpenClaw Core 更新要点

新模型与 Provider

本次新增多个模型和 Provider，模型可用性显著增强：

  • 新 Provider：Featherless、ClawRouter（bundled ClawRouter provider，credential-scoped 动态模型发现，OpenAI-compatible + 原生 Anthropic/Gemini 传输，跨 OpenClaw 各使用面统一预算报告）
  • 新模型：
    • Claude Sonnet 5
    • Mythos 5
    • Meta Muse Spark 1.1（bundled Responses API 支持，含流式、tool calls、加密 reasoning 回放、独立 npm/ClawHub 发布为 @openclaw/meta-provider）
    • GPT-5.6（新装默认模型；Sol/Terra 配 /think ultra，Luna 配 max）
    • 尊重 Z.AI 的 max
  • Nemotron Super：使用其 1M 上下文窗口
  • OpenRouter：保留显式 auth headers
  • OAuth 续期后刷新模型可用性

Control UI 与原生 macOS 聊天

Control UI 全面重构为「会话优先」：

  • 极简可搜索侧栏：会话成为主入口，搜索更直接
  • 紧凑上下文环（Context Ring）：上下文使用可视化更清晰
  • Reasoning Effort 滑块：reasoning 强度可调
  • 更干净的 Dashboard：去掉冗余 chrome
  • macOS 原生会话浏览器：原生窗口 + 模型/思考选择器 + 斜杠命令 + 记录导出 + 上下文用量
  • 会话优先导航：Control UI 默认 session-first
  • 侧栏导航：小尺寸可定制 pinned 目的地，剩余页面放 More，Settings 移至 footer，浏览器持久化定制
  • 侧栏用量：移除 expanded 侧栏的 provider 用量配额行（仍可在聊天 composer 与 Usage 页查看）
  • 消息上下文：从 timestamp hover/activate 显示单条消息的 token/上下文/模型细节（不再有独立 Context 按钮）
  • 会话标题：reveal 截断的最近会话名（带 reduced-motion 兼容 hover 动画）
  • 新会话置顶：新创建的会话保持在稳定侧栏顺序首位
  • Skills 筛选器：agent 与 search 控件对齐，使用翻译标签
  • GitHub 预览：hover 与键盘聚焦卡片显示 issue/PR 状态、标题、作者、活动、评论、变更统计
  • Logbook 工作日志：disabled-by-default bundled 插件，将配对节点屏幕快照转为私有时间轴/每日站会/时间轴问答（plugin-contributed Control UI tab）
  • Skills 文件预览：大文件 offscreen-contained text chunks 保持响应性

Conversational Onboarding（Crestodian）

全新的智能体循环式引导，覆盖 CLI、web install、macOS app：

  • 真实 agent-loop setup：跨 CLI / Gateway / web install / macOS
  • AI 引导的 Provider 配置
  • 模型判定的审批：精确绑定具体操作
  • 脱敏凭证输入
  • 无模型时的确定性 fallback
  • 类型化操作、精确审批绑定、隔离会话转录、安全交接

离线与语音移动聊天

iOS / Android 在网络不佳时仍可用：

  • iOS / Android 离线：预绘制 bounded per-gateway 会话/转录缓存
  • Apple Watch 完整语音回合：可在 Watch 上口述消息并听到回复
  • iOS TTS 播报：通过配置的 Gateway TTS 朗读回复（含 on-device fallback）
  • Gateway TTS RPC：新增 operator-scoped tts.speak，返回整段语音给远端客户端

会话组织与生成标题

  • 生成的会话标题：通过 utility-model 路由为新会话生成简短标题（默认/每 agent 的 utilityModel 路由）
  • Gateway-backed 分组：web / iOS / Android 跨端可见
  • 未读状态、重命名、Fork、归档、删除
  • 分组管理

Telegram 与 Codex 续聊

让用户能跨轮次主动控制：

  • Codex 私聊 /login 配对
  • /steer 和 /tell：在 Codex 运行中实时操控活跃回合
  • 缺失 transcript ack 时保留消息
  • durable turns 安全采用
  • Telegram 格式/限流失败时恢复最终发送

启动与升级恢复

容器升级不再卡死 Gateway：

  • 容器迁移先于 Gateway readiness：复用挂载状态时先跑版本化 state 迁移和插件收敛
  • 不再让可恢复 legacy 状态阻塞启动
  • control-plane-safe mode：重复 unclean 启动后进入，避免 restart flapping
  • EX_CONFIG 退出：致命配置错误时 systemd / launchd 不再反复重启
  • 持续化启动结果：boot outcomes 可观测

Meta Provider 独立化

  • muse-spark-1.1 Responses API 支持：流式、tool calls、加密 reasoning 回放
  • Onboarding 集成
  • exact-model live validation
  • 独立 npm/ClawHub 分发：@openclaw/meta-provider

Android Chat

  • Agent 选择器：在 live chat 屏幕直接切换活跃 agent，chat / Talk mode / home canvas 共享 canonical session
  • 代码高亮：Kotlin / Swift / TypeScript / JavaScript / Python / Bash / JSON fenced 代码块带主题感知语法高亮
  • 硬件键盘：物理键盘 Enter 发送，Shift+Enter 换行
  • 推送对讲生命周期：PTT 准备与应用前台/Mic 所有权串行化

CLI 与 Node 工作流

  • openclaw attach：新增 attach 命令
  • 节点 context-path 支持
  • 可执行的设备审批恢复指引
  • CLI 会话软恢复：prompt 元数据变化时软恢复
  • 更清晰的插件安装退出诊断

Cron 与用量

  • 退出触发的调度
  • detached session-targeted runs
  • in-flight job doctor warning
  • Telegram usage footer 换行更友好

本地推理与聊天控制

  • Ollama 自动发现：自动发现 Ollama 推理节点
  • Lean local-model tools：从 lean agent 工具面裁剪媒体生成 / TTS / PDF 工具（保留显式配置/运行时 opt-in）
  • Tool Search fallback：exec 始终可见，避免 deferred tool search 选错工具族

Doctor 与诊断

新增多项 doctor 检查：

  • auth-profile findings
  • workspace findings
  • device-pairing findings
  • channel-plugin findings
  • memory-provider findings
  • systemd exhaustion
  • Windows LAN firewall
  • 策略修复预览：doctor --fix 期间显示 review-required 改动，但不应用

Messaging 能力扩展

  • iMessage 原生投票
  • Telegram Codex 配对与 steer
  • Telegram 多 lane 进度汇总
  • Signal target aliases
  • Telegram 多项修复：retry restart-dropped media、survive transient polling errors、dead-letter poison updates、保留转发的富文本、plugin callbacks 路由、进度更新单稳定多行窗口、自托管 Bot API 容器路径通过 trusted host roots、Telegram 拒绝 rich final reply 时安全 fallback

原生应用与本地化

  • iOS：现代化 presentation / Chat / Talk / onboarding / reconnect
  • iOS Gateway speech providers
  • iOS QR onboarding 与协议恢复
  • macOS：从 Finder 安装本地 Gateway
  • Apple/Android 核心界面本地化：新增瑞典语移动本地化

关键修复精选

  • Codex runtime switching：bundled Codex runtime 同时支持 codex/* 与 openai/* 路由
  • SecretRef 模型凭证：解析后的 provider secrets 走 process-local sentinels，仅在最终网络/provider-plugin 边界注入明文
  • Telegram token 脱敏：日志传输跨 chunk 时也能脱敏 bot tokens
  • Telegram durable turn 采用：spooled 更新仅在 durable agent adoption 后完成，避免恢复泄漏过时/重复回复
  • Task delivery recovery：规整 legacy delivery 状态，让老任务可恢复运行
  • Diagnostics provider evidence：每次完整或失败的模型调用 emit 一个去重的 provider.request timeline 事件
  • Browser actions on Node 24：Node 24.16+ 的提前 abort body-stream 信号不再影响 valid POST actions
  • OAuth 刷新争用诊断：本地锁路径不暴露给用户，保持结构化 provider/profile 分类
  • Exec approval prompts：背景禁用 fallback 警告只在命令真正前台运行时显示
  • Direct poll 投递：通过 owning outbound adapter 路由 direct/hybrid polls
  • Microsoft Teams Graph 响应边界：限定文件上传/聊天 JSON 读取上限
  • Packaged speech runtime：npm 安装时 TTS 启动恢复
  • Plugin update reliability：保留通过 ClawHub 成功切换的插件
  • Codex app-server 协议：要求 0.143+，移除 pre-0.142 兼容性，迁移 on-failure 到 on-request，管理运行时升级到 0.144.1
  • CJK Markdown 强调：相邻中文/日文/韩文标点不再泄漏字面标记
  • Backup 重试清理：Windows EBUSY 锁不再级联到后续 attempt
  • Codex yielded native subagents：parent app-server 订阅与共享 client 保持存活直至完成投递
  • Delivery recovery pacing：网关启动后合格出站/replay 节拍放慢，避免 channel rate limits 突发
  • Outbound pre-connect recovery：清掉 stale platform-send 证据，连接失败后可重放
  • Discord 流式 final：完成回复作为新消息发送，让不活跃频道变未读
  • OpenAI-compatible SSE parsing：识别被错误标为 JSON 的事件流，不再二次加 data: 前缀
  • Meta Model API 契约：使用当前 Meta 端点与 output-token 字段
  • LM Studio embedding 预加载：尊重 model/provider 上下文窗口限制，避免 OOM
  • Provider overload 分类：限流响应被分类重试/fallback
  • Agent auth 复制顺序：复制凭证时保持源 agent 的 portable auth-profile 优先级
  • Memory session repair：日常 dreaming ingestion 簿记在 session-corpus audit 之外
  • Remote browser CDP 策略：允许配置的 CDP 控制主机通过既有 hostname allowlist
  • Config unset 诊断：解释为何继承/默认配置不能 unset
  • Crestodian command probes：包含 stdout/stderr 流失败
  • Feishu mention forwarding：bot Open ID 不可用时 fail closed
  • Cron edit delivery：保留隐式投递模式
  • Telegram durability：restart-dropped media 重试，survive transient polling errors，dead-letter poison updates
  • Cross-channel inbound media：保留 caption，无法物化 inbound media 时显示 unavailable-attachment 通知
  • Agent and context reliability：保留运行时覆盖、steered subagent、fallback tool-call hints 等
  • Provider 与网络安全：Moonshot / MiniMax / Anthropic OAuth / Discord / Matrix / SMS / browser / update / embeddings / Tlon / Inworld 路径响应边界
  • Channel delivery 与 routing：Slack 回复保留在活跃 thread、保留 account-bound 投递路由
  • Cron correctness：保留 provider/model 选择，保留 startup catch-up deferrals
  • Memory 与 session 恢复：检测未索引转录、保留 notes、避免跨目录恢复
  • Windows 与执行：Windows allowlist 路径验证、PATHEXT 传播、路径大小写规范化
  • 移动端与 UI 稳定性：iOS chat 换行/最终回复保留、Android pairing/TLS 恢复、过期 pairing 卡隐藏
  • Codex 与审批流：ChatGPT 认证报告正确、破坏性审批模式重命名为 ask
  • 配置与插件健康：限制 config 遍历到 own properties、保留 config-health 恢复状态
  • Runtime process safety：防止 SSH tunnels/supervisors/MCP stdio 中的未处理子流错误
  • Node runtime 兼容性：安装器/CLI launcher/doctor/macOS app 拒绝不兼容的 Node 23
  • SQLite WAL safety：要求带 patch 的 SQLite runtime 版本的 Node
  • Installer 临时文件清理：下载/rewrite 失败时清理 Node staging 与 pnpm workspace rewrite
  • QQBot media delivery：sandbox 生成媒体发送限定在 active session 的 workspace

其他值得关注的修复

  • TUI 流式：实时渲染 delta-only 事件
  • Model 别名：provider-qualified aliases 在 session/chat-command 模型切换时解析，无冲突
  • TUI 新会话 hook：通过共享 Gateway 生命周期创建 /new 会话
  • TUI abort 诊断：为中止运行展示脱敏的工具参数验证摘要
  • iOS Watch 回复：排队 quick replies 持久化在 gateway-scoped outbox，幂等投递
  • iOS Gateway auth retry：仅在解析 loopback 主机时重试存储的 device token
  • Bedrock Mantle 发现：限制 model-catalog 拉取时间与响应大小
  • Discord thread-title 提示：UTF-16 边界截断生成的标题消息与频道上下文
  • Telegram durable turn adoption：complete spooled updates only after durable agent adoption
  • Telegram token redaction：redact bot tokens even when log transports split them across chunks
  • Memory wiki unparsed YAML：gracefully handle unparsable YAML frontmatter in vault scans
  • OpenAI image quality/moderation CLI 选项：expose
  • 对话/审查控制：scoped conversation capability profiles、Cursor Agent 作为 autoreview 引擎
