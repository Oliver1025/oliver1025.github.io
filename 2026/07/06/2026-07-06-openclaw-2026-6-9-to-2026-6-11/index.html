OpenClaw 更新解读 (2026.6.9 → 2026.6.11)

本次版本跨度约 2 天，合并 PR 共 308 个。OpenClaw Core 升级到 2026.6.11，微信插件（openclaw-weixin）维持 2.4.4 不变。本次重点在 多通道控制能力增强、Operator 工作流工具、插件分发安全 与 Agent 长期稳定性。

OpenClaw Core 更新要点

多通道控制能力

各 IM 通道的可控性进一步增强，便于自动化和按场景调优：

  • Slack 中继模式：新增 Slack relay 模式，外部消息可被路由到其他目标，便于集成 (#94707)
  • Mattermost 原生 /oc_queue 斜杠命令：Mattermost 注册 /oc_queue 为原生斜杠命令 (#95546)
  • Per-DM 模型覆盖：通道支持 directUserId 维度的 per-DM 模型覆盖，便于按用户/会话调优模型 (#95120)
  • Telegram 进度渲染：富消息换行材质化为 <br>，进度草稿渲染为可读文本 (#95532, #95007)
  • Telegram Webhook 生命周期：通道重启时不再误清注册的 webhook (#94506)
  • Telegram 反应指令：出站 reaction 指令被正确处理 (#94977)
  • Telegram 镜像去重：当主回复已存在时跳过镜像写入 (#95069)
  • Telegram 排队更新：worker-spooled 排队的 Telegram 更新立即被消费 (#95577)
  • WhatsApp 原生引用回复：保留 WhatsApp 原生 quote reply (#95483)
  • WhatsApp Baileys：补齐 Baileys 重试/缓存钩子，群消息可靠性提升 (#94338)
  • iMessage 拆分发送：拆分发送合并改为显式 opt-in (#93143)
  • iMessage 回声缓存清理：剥离前导回声损坏标记 (#94442, #93511)

Operator 工作流工具

  • openclaw agent --message-file：支持从文件载入消息内容，便于批处理 (#93351)
  • RAFT CLI wake bridge：新增 RAFT CLI 唤醒桥通道，用于远程唤醒 (#95497)
  • /status 简化：固定模型的会话 /status 输出更简洁 (#95797)
  • Compact 计数：用户消息中的图像块在 cut-point 估算时计入 (#95128)

插件分发与图标

  • 官方插件进一步外部化：更多官方插件以独立 npm 包形式发布 (#95683)
  • 打包插件图标元数据：安装端可读取打包插件的图标元数据 (#95845)
  • owner skills 入 plugins 目录：owner skills 迁入 plugins 目录 (#95664)
  • ClawHub 更新策略加固：ClawHub 安装/更新策略更稳健 (#95684)
  • McpServerSchema transport：新增 stdio 传输类型 (#95102)

Android 移动端

  • 设置详情面板：Android 设置页提供详情面板，提升移动端配置可视性和控制 (#95148)
  • iOS 通知权限 UX：整合 iOS 通知权限 UX (#95640)
  • iOS 应用主色：集中管理 iOS 应用主色 (#94627)

Agent 长期稳定性

  • Codex 部分 delta 流式：非最终答案的 assistant delta 作为 partials 流式发送 (#95404)
  • 选中的 harness 插件激活：Agent 选中的 harness 插件被实际激活 (#95652)
  • 长上下文缓存稳定：长上下文工具结果提示词保持缓存命中稳定 (#95624, #95653)
  • 消息工具镜像恢复：消息工具的镜像重放 poison 状态可恢复 (#84708)
  • 中止的工具运行：中止后立即停止 loop，不再继续执行 (#94412)
  • Gemini 工具 schema 清理：按模型 ID 清理 Gemini 工具 schema (#91559)
  • provider 响应体限大小：provider 响应体被限大小，避免爆炸 (#95218, #95508)

Gateway / 会话安全

  • 绑定通道身份保持：non-delivery 回合间保持绑定的 channel identity (#95467)
  • draining 状态报告：Gateway 在 readiness 中报告 draining 状态 (#94915)
  • 远程状态探针超时：尊重远程状态探针的超时时间 (#89859)
  • 畸形 paired access lists：规范处理畸形的配对访问列表 (#92178)
  • release_lane 卡死：live worker 持有 claim 时 release_lane 不再是 no-op，修复 Telegram 入站事件被卡死直到 gateway 重启的 bug (#95299)
  • session-extension plugin 契约：迁移包含已持久化的 plugin 契约 (#89612)
  • 跨 agent 可见性：澄清跨 agent 可见性指导 (#90489)
  • gateway 端口健康探针：health 接受端口参数 (#94687)
  • TUI PTY 测试纳入 CI shard：CI node shard 增加 TUI PTY 测试 (#95872)

Provider / 模型边缘场景

  • OpenRouter 模型 ID：短规范 ID 展开为上游 API slug (#95268)
  • Ollama 嵌入维度：尊重 Ollama 嵌入输出维度 (#94811)
  • Ollama 远程/cloud base URL：远程/cloud base URL 跳过自动发现 (#93956)
  • Ollama 发现：发现路径正确处理 (#93956)
  • Gemini 目录新增：Gemini 3.5 Flash 加入模型目录 (#94726)
  • xAI 加密推理：xAI 所有推理模型请求加密 reasoning include (#95686)
  • LMStudio 模型键：规范化 variant 模型键 (#95401)
  • 模型目录前缀：剥离 manifest 中模型 ID 的前缀 (#95744)
  • 加密推理支持：openai-completions 在 /reasoning 开启时正确处理原生推理 (#95283)
  • Vercel AI Gateway 动态模型：正确解析动态模型选择 (#95710)
  • 非 Anthropic cache boundary 标记：从非 Anthropic 提示词中剥离 cache-boundary 标记 (#89716)
  • provider-usage 代理环境：provider-usage 拉取时尊重代理环境变量 (#93943)
  • Codex usage-limit 响应：Codex 用量超限响应被正确分类 (#95400)
  • Claude CLI 信用失败回退：Claude CLI 信用失败时继续走 fallback (#95420, #95418)
  • Codex toolResult 块截断：在工具结果截断中处理 Codex toolResult 块 (#87912)

配置 / UI 安全护栏

  • 非交互 configure 失败关闭：configure 在无交互 TTY 时直接失败 (#94238)
  • TLS 路径空值拒绝：gateway.tls 拒绝空白 certPath/keyPath (#94054)

  • 隐藏子 agent 页面：web-ui 跳过隐藏的子 agent picker 页 (#89323)
  • provider 用量配额显示：侧边栏 session 切换器恢复 provider 用量配额 pill (#94219)
  • 持久历史文本块渲染：持久化的历史文本块正确渲染 (#93841)
  • OpenAI 图像选项 CLI：暴露 OpenAI 图像 quality/moderation CLI 选项 (#94156, #95300)

Cron 与投递校验
