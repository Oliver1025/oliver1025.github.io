OpenClaw 更新解读 (2026.5.28 → 2026.6.9)

本次版本跨度约 12 天，合并 PR 共 422 个。OpenClaw Core 升级到 2026.6.9，微信插件（openclaw-weixin）维持 2.4.4 不变。本次重点在 Telegram 富文本投递、Agent 恢复能力、Codex 集成 与 官方 Provider 插件独立化。

OpenClaw Core 更新要点

Telegram 富文本投递全面升级

本次 Telegram 通道做了大量重构，现在能更忠实地渲染富文本和 Markdown：

  • HTML 富消息：富消息改为以 HTML 形式发送 (#93286)
  • Markdown 保留：富消息里的换行、代码块、链接能正确保留 (#93164)
  • 贴纸路径：发送贴纸时不再丢失原始 media 路径 (#93130)
  • 进度草稿：进度草稿和命令输出渲染为富预览 (#93124, #93364)
  • HTML 表格：HTML 表格被安全地规范化（防 XSS / 结构破坏）
  • 入场消息恢复：修复因 PID 复用导致的入口消息声明丢失 (#93281)
  • 降温逻辑：瞬时 sendChatAction 失败会自动降温，避免日志刷屏 (#93020)

Agent 恢复能力

断流、异常、空响应等场景下的处理变得更稳健：

  • 空工具回合重试：仅思考错误回合、工具后空回合都会重试 (#92191, #93073)
  • Hook 幂等性：wrapToolWithBeforeToolCallHook 改为幂等，避免重复执行 (#93009)
  • 使用量保留：压缩后仍保留最新的 token 使用量数据 (#93084)
  • 截断检测：检测 API 响应截断，避免静默挂起 (#89160)
  • 断连分类：不再把客户端断连误判为运行超时 (#90936)
  • 会话修复：自动修复部分 JSON 与历史记录残缺 (#94349, #92383)
  • 子 Agent 投递：保留待投递的子 Agent 回复，避免丢失 (#94257)

Codex 集成增强

  • 自动插件审批：Codex 集成支持自动插件审批 (#92625)
  • GPT-5.3 Spark OAuth：恢复 Codex Spark OAuth 路由 (#89133)
  • 远程节点 exec：远程节点的 exec 作为动态工具暴露给 Codex（需先连接节点）(#93654)
  • 一次性会话清理：修复一次性 Codex app-server 清理逻辑 (#91767)
  • 终端结果保序：Codex 终端结果顺序保持稳定 (#93287)
  • 评论去重：Codex 原始响应通道内的评论笔记去重 (#93343)

官方 Provider 插件独立发布

第三方 Provider 包现在以独立 npm 包形式发布，Gateway 启动时会自动发现已安装的渠道插件：

  • StepFun 上线：可通过 npm 或 ClawHub 安装 StepFun (#93470)
  • 外部 Provider 包：作为一等公民的 npm 发布渠道
  • 渠道插件加载：Gateway 启动时发现已安装的渠道插件

控制面板与移动端

  • 会话工作区栏：Control UI 新增 session workspace rail (#92856)
  • 插件健康度：status 命令现在展示插件健康度 (#91952)
  • 紧凑 Cron 列表：Cron 列表更紧凑 (#93395)
  • iOS Watch 控制：iOS 端支持 Apple Watch 控制 (#93387)
  • Android 聊天上下文：Android 端展示实时聊天上下文用量 (#92837)
  • iOS 安全区：聊天头部尊重安全区 (#91768)
  • 权限刷新：iOS 端授权后权限行实时刷新 (#91776)

搜索与技能

  • Codex Hosted Search：开放 Codex 托管搜索能力 (#93446)
  • 免密钥搜索：免密钥搜索提供商保持显式 opt-in
  • ClawHub 技能来源保留：ClawHub 安装的技能保留验证来源记录 (#93283)
  • Skill 文档：ClawHub 内容权益文档加入侧边栏 (#93489)

安全与隐私

  • 密钥脱敏：debug/config 输出中自动遮蔽密钥 (#93333)
  • 内部 HTTP 覆盖拦截：阻止内部 HTTP 会话覆盖 (#93443)
  • 开放 DM 工具审计：审计开放 DM 工具的暴露面 (#88496)
  • 插件写入所有权检查：插件写入需 owner 校验 (#93353, #92883)

存储与迁移

  • 网络文件系统：SQLite 在网络文件系统上不再启用 WAL (#93454)
  • 重索引清理：清理过期的重索引临时文件 (#92891, #93182, #93295)
  • 工作区目录保护：设置状态不写入工作区的 dot 目录 (#93520)
  • 默认 Agent 认证导入：doctor 将默认 agent 的认证配置导入 SQLite (#93156)
  • SQLite 路径缓存：加固 SQLite 路径缓存 (#88792)

Provider 与模型行为

  • Gemini CLI 代理 OAuth：通过环境代理路由 Gemini CLI OAuth (#92815)
  • Codex Spark OAuth：恢复 GPT-5.3 Codex Spark OAuth 路由 (#89133)
  • Bedrock 嵌入：修正 Bedrock 嵌入模型 ID (#93452)
  • runEmbeddedAgent 默认模型：嵌入式运行解析配置中的默认模型 (#93428)
  • 认证别名兼容：保留 alias-compatible 的认证配置覆盖 (#85316)

CLI / TUI / 应用

  • 全局标志位置：接受子命令后的全局标志 (#93455, #93324)
  • –log-level 生效：route-first 命令的 --log-level 现在生效 (#93460)
  • 终端输出：本地 shell stdout 填满时 stderr 仍可见 (#93006)
  • CJK IME：保留 CJK 输入法组合状态 (#93427)
  • 活动指示器：系统注入的运行也展示活动指示器 (#93498)
  • Discord 超时：允许 Discord 超时为 0 (#93329)
  • 代理安全区：iOS 端聊天头部尊重安全区 (#91768)

定时任务（Cron）

  • cron edit --clear-model：清除定时任务的模型覆盖 (#91625)
  • lastRunStatus：人类可读的 cron list/show 现在解析 lastRunStatus (#93245)
  • 保留调度策略：Cron 保留调度回合的工具策略 (#91499)
  • cron edit 路由清理：cron edit 清理投递路由字段 (#93495)
  • 投递证明：要求显式的消息目标证明 (#92318)

更新与运维

  • 官方插件恢复加固：加固官方插件的恢复流程 (#93325)
  • 更新交接失败：管理型 Gateway 在更新交接失败后自动重启 (#92111)
  • Cron 投递默认：保持安全的 cron 投递默认值 (#93650)
  • npm 前缀：避免 Node 专有的 npm 前缀 (#94453)

杂项修复

  • Dreaming 日记：修复「第一天」叙述重复的 bug (#91225)
  • 截图转 WhatsApp：WhatsApp 转换不再吞掉紧跟数字的 code span (#93409)
  • 媒体发送失败：WhatsApp 末尾媒体发送失败时通知用户，不再静默丢弃 (#93334)
  • Discord 工具进度：消息工具回复不展示工具进度 (#93412)
  • Discord 实时咨询：拒绝格式错误的实时咨询调用 (#93308)
  • Discord 公会管理：阻止跨 Provider 的公会管理动作 (#93354)
  • Telegram 群组历史：可控的 Telegram 群组历史上下文 (#89547)
  • Matrix 进度行：替换已恢复的命令进度行 (#89920)
  • 飞书卡片：飞书通道透传 card_msg_content_type 以获得完整卡片内容 (#93134)
  • QQ Bot 表格：QQ Bot 表格分块保持合法 Markdown (#92428)
  • Voice Call Twilio：保活 Twilio 实时流媒体 (#90812)

微信插件（2.4.4）

本次 openclaw-weixin 插件无版本变化，仍为 2.4.4。微信通道相关改进主要来自 OpenClaw Core 端的统一优化（如子 Agent RPC 回调正确路由回微信 session key 等 #90231）。
